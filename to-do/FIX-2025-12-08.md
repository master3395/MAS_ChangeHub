# Contabo Snapshot Manager - Fix Report
## Date: 2025-12-08

## Problem Identified

The snapshot manager failed on 2025-12-08 with the following error:
```
[2025-12-08 01:00:21] ERROR: HTTP error 402: {"message":"Total snapshots exceed the total max limit of 3 snapshots","statusCode":402}
[2025-12-08 01:00:21] ERROR: Failed to create snapshot: CP-2-4-4-Alma-sieve-1 - false
```

### Root Cause

1. **Race Condition**: Two instances of the script were running simultaneously
   - First instance successfully deleted old snapshot and created new one
   - Second instance tried to create snapshot but hit the 3-snapshot limit
   - No lock mechanism existed to prevent concurrent execution

2. **Insufficient Error Handling**: 
   - Script didn't verify snapshot deletions before attempting to create new ones
   - No retry mechanism when hitting snapshot limits
   - No verification of current snapshot count before creation

## Fixes Implemented

### 1. Lock File Mechanism
- Added `acquireLock()` method to prevent concurrent script execution
- Uses file locking (`flock`) with non-blocking mode
- Automatically removes stale locks (older than 1 hour)
- Lock is automatically released on script exit via shutdown function
- Lock file location: `/home/contabo-snapshots/logs/snapshot-manager.lock`

### 2. Improved Snapshot Cleanup
- Added verification step after deleting snapshots
- Waits 2 seconds after deletion for API to process
- Re-fetches snapshot list to verify deletions succeeded
- Logs warning if snapshot count still exceeds limit after cleanup

### 3. Enhanced Snapshot Creation
- Verifies current snapshot count before attempting creation
- If at limit, attempts emergency cleanup before failing
- Added retry mechanism when hitting 402 error (limit exceeded)
- Better error messages with current snapshot count information
- Returns boolean to indicate success/failure

### 4. Better Error Handling
- Checks snapshot count before and after operations
- Handles 402 errors specifically with retry logic
- More detailed logging at each step
- Graceful handling of edge cases

## Code Changes

### New Methods Added:
- `acquireLock()` - Prevents concurrent execution
- `releaseLock()` - Cleans up lock file

### Modified Methods:
- `cleanupOldSnapshots()` - Now verifies deletions succeeded
- `createSnapshot()` - Added pre-creation checks and retry logic
